# P1-A：章节地图两层化 + Hall 数据驱动升级

日期：2026-11-22
范围：**只改页面结构与展示层**，不改战斗、掉落、经济与关卡数值；实体扩张（3 角色 / 5 武器 / 6 饰品）留在 P2-1。

## 1. 交付摘要

| 块 | 改动 | 结果 |
|---|---|---|
| 章节地图 | `map.js` 重写为「章节卡一层 / 关卡节点 + 详情面板二层」 | 六章卡 3×2；章内节点 5–9 关自适应；点节点选中、Enter/「开始行动」进 Select |
| 章节预览 | 一层底部显示选中章的首领 / 出没怪 / 支线 / 隐藏 / 条件数量 | 不进场也能判断这一章大概有什么 |
| 关卡详情 | 二层面板显示标题、本章星数、基础难度、压力、Boss、出没怪、奖励、特殊内容统计 | 难度入口、开始按钮都在面板内 |
| 难度覆盖层 | 保留 P0-2 三档；重写地图后重开、切档、重建节点 | 入口在关卡面板「难度 普通 ›」 |

## 2. 地图层级与交互

```
Title
  └─ Map · chapters（六章卡 3×2，底部章预览）
       ├─ 点已解锁章 / Enter → Map · stages（节点路径 + 详情面板）
       │    ├─ 点节点：只选中，刷新详情
       │    ├─ Enter / 「开始行动」→ Select（带 chapterId/stage/difficulty）
       │    ├─ 点「难度」→ 三档覆盖层（P0-2）
       │    └─ ESC / 右键 / ← 章节 → 回 chapters
       └─ 点锁定章：只 toast，不进场
            └─ ESC / 右键 / ← 返回 → Title
```

- 节点最多 5 个/行；6–9 关折两行，按 `ceil(n/2)` 分行并居中，避免 6 关出现「5+1」的孤行。
- 章节卡显示：章名、主线星数/通关数、三档难度印记（普✓/噩✗/地✗）、主题色底条、锁定提示。
- 二层节点显示：第 N 关/首领、房数、当前档星级、可进入状态；Boss 节点用暖红底。
- 章节卡点击直接进二层；键盘可在两层内移动，Enter 在二层才出发。

## 3. Hall 两页

### 武器页

- 六卡 3×2，卡高 112，行距 124；左色条 + 稀有度边框（普通灰 / 精良绿 / 稀有蓝 / 史诗紫）。
- 卡内信息：名称、稀有度、类型、`伤×倍率 / 冷却 / 射程`、近战击退或远程弹速+穿透、解锁状态。
- 未解锁：显示 `解锁 N 宝石`，点击购买；已解锁：显示 `已解锁 · 进掉落池` + `权重 x.x`。
- 价格全部来自 `weapons.json` 的 `unlock.cost`，不再读场景常量。

### 角色页

- 三卡数据驱动，卡高 240；显示名称、稀有度、定位 tag、HP/攻/速、初始武器、技能名 + 技能描述。
- 装备位以 `护符 / 饰品` 文字占位，消费 `chars.json` 的 `slots`；本轮不做装备栏交互。
- 未解锁显示底部 `解锁 N 宝石` 按钮；已解锁显示 `可选`。
- 锁定角色的属性区只保留三行，价格只放底部按钮，避免和技能标题重叠。

## 4. 关键修复

| 问题 | 原因 | 修复 |
|---|---|---|
| 二层初次渲染 `Cannot read properties of undefined (reading 'y')` | `renderStages()` 先 `buildNodes()` 后 `buildPanel()`，`layoutPanel()` 访问尚未创建的 `panel` | 改为先 `buildPanel(c)` 再 `buildNodes(c)` |
| 6 关章节出现 5+1 孤行 | 固定 `perRow = min(5,n)` | `perRow = n<=5 ? n : ceil(n/2)`，每行按实际数量居中 |
| 难度覆盖层副标题被第一行盖住 | 副标题 y=94，首行矩形 top=97 | 覆盖层加高到 264，标题/副标题上移，行距 120/156/192，底注 232 |
| 锁定角色页「未解锁 · N 宝石」压住技能标题 | 属性区三行 + 底部按钮重复显示价格 | 锁定态属性区去掉价格行，价格只留底部按钮 |
| 武器卡右侧重复「掉落池」 | 左侧已写「已解锁 · 进掉落池」 | 右侧改为 `权重 x.x`（读 `poolWeight`） |
