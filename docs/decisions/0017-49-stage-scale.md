# ADR 0017 · 规模定稿：六章 49 关、单关房数随章递增

日期：2026-11-21
状态：已采纳（`web/data/chapters.json` v1 已落）

## 背景

v3 定的是五章 41 关、每关固定 5 房。评审时用户选择"后期加长"，明确要 50 关左右：章节越靠后关越多、难度越高。

## 决策

1. **六章主线 36 关**：5 / 6 / 7 / 8 / 9 + 终章 1；单关房数 5 / 6 / 7 / 8 / 10，终章三阶段。
2. **总量 49 关**：主线 36 + 支线 6 + 隐藏 3 + 条件 4；147★，100★ 开无光回廊。
3. **章内再递增**：第 N 关乘 `1 + 0.05 × (N−1)`，第五章末关实际 ×2.24。
4. **房间总数 328**，全部走 `chapters.json` 表驱动：章 id / 主题 / 关数 / 每关房数 / 难度 / 压力机制 / Boss 池 / 怪池 / 解锁条件。`play.js` 不写逐关分支。
5. **后期长关的节奏纪律**：10 房关只出现在第五章，中段必放商店或休整，避免一口气 10 房疲劳。

## 后果

- 批 9 的 `chapters.json` 结构先定下来（已提交 v1），后续加内容只改表，不改代码结构。
- 内容量翻倍，必须坚持"表驱动 + 通用编排"，禁止逐关手写。
- 满星时长预计 10 小时以上；这是"大作"规模的代价，验收按批次而不是按总时长切。
