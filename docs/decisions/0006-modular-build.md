# ADR 0006：源码模块化与引擎分离

- 日期：2026-11-19
- 状态：已实施，两种运行模式均实测通过
- 上游：ADR 0003（技术栈）、ADR 0005（房间结构）

## 背景

P2 之前所有逻辑塞在 `web/main.js` 一个文件里，构建脚本把它和 Phaser、素材一起 base64 内联成 1.26 MB 的 `game.html`。这套"单文件"有三个实际问题：

1. 改一行数值，玩家要重下 366 KB（gzip）；
2. 819 行代码挤在一个作用域，加内容必然变成维护灾难；
3. 以后要上原生壳（Capacitor）时，每次热更新都会整包重下。

## 决策

**源码分模块，引擎与资源分开交付，单文件版降级为本地自测工具。**

### 目录

| 路径 | 职责 |
|---|---|
| `src/main.js` | 入口：装配 Phaser、处理自适应尺寸 |
| `src/core/config.js` | 全部常量与手感数值（改数值只改这里） |
| `src/systems/dungeon.js` | 地牢拓扑生成（纯函数，不碰渲染） |
| `src/scenes/boot.js` | 加载素材、建动画、跳转 |
| `src/scenes/play.js` | 主场景：移动/战斗/房间/门/掉落/Boss/HUD |
| `tools/build.mjs` | esbuild 打包 + 生成 Pages 入口 + 单文件自测版 |

### 产物

| 文件 | 内容 | 缓存策略 |
|---|---|---|
| `index.html` | Pages 入口，815 字节 | 不缓存 |
| `web/vendor/phaser.min.js` | 引擎，1154 KB（gzip 305 KB） | 路径固定，可长期缓存 |
| `dist/assets.<hash>.js` | 素材 base64，85 KB（gzip 54 KB） | 文件名带 hash |
| `dist/game.<hash>.js` | 游戏逻辑，19 KB（gzip 6 KB） | 文件名带 hash |
| `web/game.html` | 全内联单文件，1259 KB，仅供本地双击自测 | 不进 Pages 主链路 |

hash 由内容 sha256 前 8 位生成，内容不变文件名不变，改了才变——这是"只下差异"的前提。

## 代价与实测

- **冷启动没有变快**：首次访问仍是 305 + 54 + 6 ≈ 365 KB（gzip），与旧单文件 366 KB 基本持平。原因是引擎本身就占 83%，拆包不减少首次下载量。
- **真正的收益在更新**：改玩法只重下 6 KB，改美术重下 54 KB，引擎不再重下。按旧方案每次都是 366 KB。
- **本地自测多一步**：`web/game.html` 仍可双击打开，不受影响。
- **构建需要 Node + esbuild**（`npm install` 一次，esbuild 已在 devDependencies）。

## 否掉的方案

- 直接上 Phaser 的模块化源码（ESM 分模块打包）：引擎体积不变，收益相同但更脆弱。
- 继续单文件、只靠 gzip：更新代价无法解决。
- 换引擎（Godot/Unity）：3D 或 Steam 才划算，当前 2D 像素路线没必要。

## 后果

第 2 步（资源管线：图集、音乐流式、按章节懒加载）和第 4 步（PWA/原生壳）都以本结构为前提，可以直接在 `dist/` 上加产物。
