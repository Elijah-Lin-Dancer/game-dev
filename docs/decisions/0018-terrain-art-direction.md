# 0018 · 地形美术方向：3D 像素套件，暂缓真多边形碰撞

- 日期：2026-11-26
- 状态：美术方向已接受；工程重构列入 backlog，不在当前第 1 关批次
- 相关：`docs/BACKLOG.md`、`docs/BATCH37-FORT.md`、`docs/ART_PIPELINE.md`

## 背景

旧堡第 1 关实机试点暴露出两个独立问题：Boss 房召唤兽阻挡（玩法），以及现有地形以 32px 方块为主、视觉上过于规整（美术）。用户确认：Boss、地形套件、关键摆件可以换；真多边形碰撞与全关卡地形重做先不做。

## 决定

1. **逻辑碰撞层保持不变**：继续使用 32px 格子、`walls` 集合、`isWall()`、`reachableTiles()`、BFS 寻路、门位与刷怪连通性检查。地形美术替换不得改动这些接口。
2. **视觉层改用 ink-studio 预渲染地形套件**：地面变体、崖壁正面、墙顶、圆角/内外拐角 autotile、高台边缘与投影、贴花。导出为固定正交俯视、有限色板、硬边缘的 sprite sheet，不做运行时 3D。
3. **允许“视觉不规则、逻辑规则”**：房间轮廓可做洞穴状、壁龛、窄口、圆角，但连通性、门、刷怪、Boss 房仍按格子校验。高台先做视觉高台，仍是不可走墙；可行走高度另立专项。
4. **第 1 关先做 pilot**：蓝武士 Boss 换 ink-studio 模型；机关石像、篝火等关键摆件替换；先改一间战斗房 + Boss 房地形做并排对比，风格确认后再铺整关。
5. **暂缓项**：真多边形碰撞地形、49 关全量地形重做，写入 `docs/BACKLOG.md`，等第 1 关 pilot 通过并确认风格后再评估。

## 后果

- 短期风险可控：碰撞、寻路、刷怪、门锁、机器人脚本不改，第 1 关实机验收可以继续复用。
- 美术一致性需要单独把关：3D 渲染必须降采样到 32px 网格、限制色板、固定光照，否则会和现有像素角色脱节。
- 真多边形碰撞若启动，需要独立分支、独立批次、49 关全量回归与性能基准，不能和内容批次混做。

## 未来触发条件

只有在以下条件同时满足时，才重新评估真多边形碰撞：

- 第 1 关 pilot 已通过，地形套件风格被确认；
- 现有格子方案在 960 / 640 下仍无法满足轮廓要求；
- 有独立时间窗重写移动、寻路、刷怪、门锁和机器人路径；
- 能接受 49 关全部重跑验收。
