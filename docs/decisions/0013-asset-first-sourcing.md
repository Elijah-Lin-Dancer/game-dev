# ADR 0013 · 素材优先：外部源可达性重测与"何时才自绘"

日期：2026-11-20
状态：已采纳

## 背景

`ROADMAP §11.3` 里写过一条结论：外部素材平台"实测不可用"（`kenney.nl` 403、`itch.io` 000），因此"天花板 = 本包 + 代码自绘"。用户对此提出了质疑：**"尽量找已经公开的素材库里边直接拿来用，别自己编码造，除非实在没法。"**

这条质疑是对的，原来的结论有两个问题：

1. **样本太小**。只试了两个站点就推出"外部不可用"的全局判断，而 `raw.githubusercontent.com` 一直是通的（Ninja Adventure 本身就是从 GitHub 拉下来的）。主站被拦不等于素材拿不到。
2. **把"找不到"和"下载不到"混成一件事**。真实约束不是"没有素材"，而是"素材风格不匹配"——这个门槛更高，也更需要逐件判。

## 决策

1. **素材优先（asset-first）**：任何视觉缺口，顺序是 ① 本包现成件 → ② 外部 CC0 现成件 → ③ 换一种表达方式绕开 → ④ 自绘。跳过 ①② 直接 ④ 视为违规。
2. **可达性以实测为准，并且按站点单独记**，不再用一两个站点代表"外部平台"。
3. **风格判定写死口径**，避免"看着差不多就用"：
   - 能直接用：16×16 平涂、调色板接近、有描边轮廓；
   - 半合：尺寸或质感不对但姿态/曲线可参考 → 只当参考；
   - 不合：32–64px 高光渐变（手游图标风）→ 不采纳。
4. **自绘只留两种合法情形**：包内外都没有合风格素材；或者需求是**动态**的（半径/颜色跟着数值变），固定帧素材天然做不到。
5. 采纳外部素材必须同时落三处：`assets/01-primary/external/`（文件）、`assets/CREDITS.md`（作者/源/许可/改动）、对应 ADR 或批次说明（为什么选它）。

## 重测结果（2026-11-20，本机）

| 站点 | 结果 |
|---|---|
| `opengameart.org` | **200**，实际下载成功：`campfire_16x16.png`(467 B)、`gems.zip`(202 KB)、`Small Sheet.png`(1.2 MB) |
| `raw.githubusercontent.com` / `codeload.github.com` | **200**（GitHub 素材镜像全部可用） |
| `kenney.nl` | 403（站点拦截；素材有大量 GitHub 镜像，改走镜像） |
| `itch.io` / `*.itch.io` | 000（连接被拒） |

四个真缺口的判定（细节见 `docs/ASSET-SOURCES.md §4.1`）：

| 缺口 | 结论 |
|---|---|
| 篝火 | **采纳** OGA `16x16 Animated Campfire`（CC0，4 帧 16×16，平涂暖色，与本包同档） |
| 宝石/水晶图标 | **不采纳**（CC BY 的 64px 高光渐变，缩到 12×12 会糊）→ 先用包内 `Items/Elemental` 五种元素图标顶替 |
| 武器挥动帧 | **不采纳文件**（发光刀光非像素）；现有代码 act FX 已成立，OGA 的曲线仅作参考 |
| 火把/灯笼发光 | **暂不采纳**（DENZI 偏精细）；径向渐变 + `Particle/Fire` 叠 ADD 已够 |

## 影响

- `ROADMAP §11.3` 从"天花板 = 本包 + 自绘"改为"外部不可靠但可用，风格匹配才是门槛"。
- 后续每个批次开工前先产出"缺口→候选→许可→风格判定"表，再动代码。批 2 起直接照这个流程走。
- 已采纳的篝火要等批 2（房间编排）真正用上时再入 `assets/01-primary/external/` 并登记 CREDITS，**不为"先囤着"入库**。

## 风险

- **许可混用**：CC BY 需要署名，CC BY-SA / GPL 一律不碰。双协议包（如 `Objects for 16x16 tilesets` 的 CC BY + GPL）只取 CC BY，且必须在 CREDITS 写明"仅按 CC BY 使用"。
- **风格拼贴感**：跨作者混用在 16px 下会被放大。规则：单个场景里外部件不超过 1 类，且必须与本包同调色板档位。
- **来源漂移**：OGA 页面可改可删。采纳时必须把文件本身存进仓库，而不是运行期外链。
