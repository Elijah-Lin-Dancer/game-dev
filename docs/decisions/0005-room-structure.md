# ADR 0005：房间结构（P2）

- 日期：2026-11-19
- 状态：已实施，自动化验证通过；待主测手感
- 上游：ADR 0003（栈与分辨率）、ADR 0004（战斗手感）

## 背景

P1 只有一间「无限刷怪」的空房间，怪杀完就再刷，没有目标、没有终点，玩起来像练习场。P2 要把它变成**一局**：有房间、有门、有掉落、有 Boss、有输赢。

## 决策

### 1. 房间尺寸与坐标

| 项 | 取值 | 说明 |
|---|---|---|
| 格 | 32 世界像素 | 16px 美术 × 2，像素感与可读性折中 |
| 房间 | 24 × 26 格 = 768 × 832 | 竖屏塞得下，横屏也不会太空 |
| 相机 | 跟随 + 夹在房间边界 | 房间大于视口，靠滚动呈现 |

每个房间是闭合的独立坐标空间，换房时整间重建（容器整体销毁重建，不累积对象）。

### 2. 地牢拓扑：3×3 网格随机游走

- 起点 (0,0)，终点 (2,2)（Boss 房）。
- 逐格四向走，不重访；每步 65% 概率直奔终点、35% 随机拐弯。
- 路径长度 ≥5 时强制直奔终点，把一局控制在 **3–6 间**。
- 相邻两格之间开一道双向门，门的位置固定在各自房间边的中点。

**否掉的方案**：手搓 Tiled 地图（要引编辑器与导出流程，P2 阶段太重）；预置房间池（内容量不够，重复感强）；纯噪声生成（连通性难保证，容易出死房间）。

### 3. 门与清房

- 门洞 3 格宽（96 px），底铺沙色地块，锁着时盖 3 块墙。
- 门格在锁着时**同时进物理墙集合**，所以玩家撞不过去，不是靠判定拦截。
- 清空房内怪 → `room.cleared = true` → 墙集合移除门格 → 门可通行。
- 从哪个门进的，就落在对面门口内侧 2.5 格，落点方向可预期。
- 允许回走：往回走不会重刷怪，掉落也还在（记录在房间上的 `dropState`）。

### 4. 敌人与 Boss

| 对象 | 血量 | 接触伤害 | 速度 | 备注 |
|---|---|---|---|---|
| Beast（小怪） | 6 | 3 | 46 | 每间 3–5 只，按房间序号递增最多 +2，上限 7 |
| GiantFrog（Boss） | 28 | 3 | 52 | 只正面 5 帧 idle，无四向表，用 flipX 表朝向 |

- Boss 生成点按玩家落点对侧放置（玩家在上半区就生成在下 28% 处），并给进门 700 ms 无敌，避免"进门贴脸秒杀"。
- Boss 房无出口，击破后 900 ms 通关。

### 5. 掉落

- 小怪：45% 掉金币、12% 掉心（回 4 血，上限 20）。
- Boss：必掉 1 金币 + 1 心。
- 金币用 `Coin2.png`（40×10 = 4 帧 10×10 旋转动画），不用 `GoldCoin.png`（那是金边框，不是币）。
- 掉落不随房间销毁：离开时把坐标存进 `room.dropState`，回来重建。

### 6. 输赢与重开

- 血 0 → 遮罩「你倒了」+ 本局统计。
- 击破 Boss → 遮罩「通关」+ 击杀 / 金币 / 剩余血。
- 点击或 R → `scene.restart()`，**重新生成地牢**（不是重进同一张图）。

## 后果

- 一局时长实测 3–5 分钟（含跑图与两次死亡重试），符合"分钟级 run"的定位。
- 房间数量与门方向随机，但结构单薄：没有小地图、没有存盘、没有宝箱房/商店房这类变体。
- Boss 只有接触伤害，没有抬手/预警，属于"能打但不讲究"的水平，留给 P3。
- 房间地形只有 4 个随机 2×2 障碍块，缺乏掩体设计；Tiled 地图仍在待办。
