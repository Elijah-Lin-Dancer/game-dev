# 批 7 · 大厅、宝石、图鉴（实施记录，2026-11-21）

## 1. 做了什么

给"再来一局"一个玩家自己决定的理由：跑完一局拿宝石，宝石在小屋解锁武器与角色，图鉴记录见过的东西。

| 块 | 实现 | 文件 |
|---|---|---|
| 宝石货币 | Boss 死掉 1–3、通关 +5；本局累计，结算（死/通关）时写进存档；HUD 信息条显示、结算层显示 `宝石 +N` | `play.js` |
| 大厅 | 新 Scene：三个页签（武器 / 角色 / 图鉴），顶部宝石数，底部「Enter 出发」→ 选人 | `src/scenes/hall.js` |
| 解锁 | 武器：短弓 15、战锤 20；角色：法师 30、骑士 40。点条目即买，宝石不够给提示 | `hall.js` + `save.js` |
| 掉落池 | 只有已解锁武器进 `W.list`，职业起始武器永远保底（空池不会把掉落打崩） | `play.js` |
| 选人锁 | 未解锁角色卡变灰、标价，选中也不能出发 | `select.js` |
| 图鉴 | 怪（10）/ Boss（2）/ 武器（6）/ 房间事件（7）四栏，首次遇见点亮，其余 `???` | `play.js` 记、`hall.js` 画 |
| 流程 | `Boot → Hall → Select → Play`；`?char=` 仍可直达 | `boot.js`、`main.js` |

**素材：0 外部件、0 自绘**。宝石图标取自包内 `Backgrounds/Tilesets/TilesetDungeon.png` 的 frame 43（蓝灰多面晶体，16×16 平涂带描边），与整包同一档像素；大厅地面用 `Interior/TilesetInteriorFloor` 322 压暗，武器图标 / 角色立绘 / 怪物首帧全部复用既有图集。

## 2. 存档 v5

```js
{ v: 5, gem, unlockedWeapons[], chars[], seen: { enemies{}, weapons{}, bosses{}, rooms{} }, ... }
```

- 老档 v4 升级：`chars` 原样保留（老玩家不会因为本批突然丢角色），`gem` 从 0 起，`unlockedWeapons` 缺省四把（刀/巨剑/杖/苦无）。
- 新档：只有忍者 + 四把武器，短弓/战锤/法师/骑士要买。
- 清洗：`unlockedWeapons` 只允许已知 id 且强制保留 `katana`；`seen` 只接受 `[a-zA-Z0-9_-]{1,24}` 的键，值统一为 1，避免坏档把巨型键带进图鉴。

## 3. 实测

| 项 | 做法 | 结果 |
|---|---|---|
| 掉落池过滤 | 未解锁弓/锤时读 `__dbg.weapons()` | `['katana','bigsword','wand','kunai']` |
| 买短弓 | 80 宝石点条目 | 花 15，`gem=65`，`unlockedWeapons` 追加 `bow` |
| 买法师 | 65 宝石点条目 | 花 30，`gem=35`，`chars` 追加 `mage` |
| Boss 掉宝石 | `boss('frog')` + 击杀 | 本局 `gems=6`（Boss 1 + 通关 5），存档 `55→61` |
| 图鉴点亮 | 打死怪/Boss、换武器、进房 | `seen` 里出现对应键，图鉴从 `???` 变为名字与头像 |
| 无报错 | 全流程监听 `pageerror` | `errs=[]` |

## 4. 已知限制

- 图鉴格子 44px，Boss 名"青蛙大王"会略微出格；武器名三字刚好顶满。属排版打磨，不影响点亮逻辑。
- 大厅只有鼠标点解锁，没有手柄/键盘选择解锁项；键盘只负责切页与出发。
- 结算后按 R 仍是"同角色再来一局"，没有回小屋的按钮；想买东西需刷新回大厅（后续可在结算层加一个"回小屋"）。
- 关卡内没有宝石掉落物实体，只有 HUD 数字与结算文本；做掉落动画属于表现力加料。
- 图鉴只记"见过"，不记次数与首次时间；统计页（最快通关、最高周目）仍未做。
