## 4. 踩到的坑（后续别再踩）

**新数据必须显式透传。** `build.mjs` 注入了 `ASSET_DATA.chaptersData`，但 `boot.js` 只把 story/weapons/talents/chars 挂到 `window`，地图里 `chapterById` 拿到 null，最终报 `Cannot read properties of undefined (reading 'id')`。所有新 JSON 都要在 `boot.js` 加一行 `window.__xxxData = ...`，光改构建不够。

**星级字体没问题，别急着换字。** 地图页眉的「·」在 2× 缩放下像一个方块，容易误判缺字；实际 Fusion Pixel 有 `★☆·—…`，截图放大即可确认。新增中文（章节名、怪名）必须走 `tools/subset_font.py`，构建会自动扫 `src/**/*.js` 和 `web/data/*.json`。

**地图两行节点要对齐第一行的列。** 9 关章节第二行只有 4 张卡时，按"本行宽度居中"会让两行错位；改成始终按 `perRow` 宽度算左边距，第二行自然与第一行同列。

**测试过门别用固定方向。** 章节地牢是蛇形路线 + 随机翻转，同一房间的"右"可能是来路；调试口 `__dbg.next()` 会找 `idx` 更大的邻房再走，适合自动跑全关。

**章节关的结算不能复用老逻辑。** 老 `win()` 会加通关次数、涨周目、提示"按 R 重开"；章节关要单独分支：算星、取最高、宝石 +2、`commitRun(false)`、Enter/点击回地图。终章才允许 `wins/cycle +1`。
