# PLAYTEST-3 · B 步手感修复验收

日期：2026-11-19
目标：把"敌人只会傻贴脸、镜头死跟、提示条被裁"这三处让玩家觉得"简陋"的地方修掉。
方法：无头 Chromium（`/usr/local/bin/chromium`）+ Playwright，`add_init_script` 注入 rAF 逐帧采样；判定标准只看运行时数值与截图，不看代码推测。

## 1. Boss 抬手预警（可读性）

`updateBoss` 改为状态机：`approach → windup(420ms，红身+抖动放大) → lunge(220ms，方向锁定后直线冲撞 190px/s) → recover(380ms) → 循环`。

实测阶段序列（玩家置于 130px 外，每 80ms 采样）：

```
windup → lunge → recover → windup → lunge → recover → windup → lunge → recover
```

三轮循环无异常、无 `pageerror`。截图 `docs/screens/b1-windup.png`：Boss 橙红染色并放大约 1.6 倍，玩家能明确读到"它要冲了"。

## 2. 伤害只在冲撞帧生效

接触伤害加门禁：`canHurt = (type === 'boss') ? phase === 'lunge' : true`。玩家贴到 72px 时逐帧记录血量：

| 阶段 | 血量 | 结论 |
|---|---|---|
| windup | 20 | 蓄力期贴脸不掉血（原来会掉） |
| lunge 结束 | 17 | 只有冲撞能命中，−3 |
| 下一轮 lunge 结束 | 14 | 节奏稳定 |
| 再下一轮 | 11 | 单次冲撞只结算一次 |

## 3. 小怪追击与命中节奏

站桩 8 秒逐帧采样（3 只小怪，从 200px 外生成）：

```
t=5225ms hp=20 → t=5925ms hp=17 → 6641ms 14 → 7358ms 11 → 8058ms 8 → 8058ms 后 5
```

间隔 632–758ms，与 `iFrame 700ms` 一致，说明既没有同帧连击，也没有卡住不动。

**小怪绕障（`updateBeast`）**：位移小于预期的 40% 时累计 `stuckT`，超过 260ms 就沿垂直方向侧滑 420ms。此项目前只有代码与数值层面的验证，**尚无"被 U 形墙卡住后确实绕过去"的定点证据**，列为待验项。

## 4. 镜头前瞻

`startFollow(player, true, camLerp=0.12, 0.12)` + 每帧按朝向给 `setFollowOffset` 喂目标值（前瞻 22px，纵向 0.8 倍），用 `1 - 0.004^(dt)` 平滑。实测（视口 640×360，居中基准 320 / 180）：

| 朝向 | 人物屏幕坐标 | 相对居中 | 说明 |
|---|---|---|---|
| 朝上 | y=197 | +17 | 视野向上让出 17px ≈ 22×0.8 |
| 朝下 | y=163 | −17 | 视野向下让出 17px |

第一次实现把符号写反（前瞻方向与朝向相反），由这组测量发现并修正；朝右/朝左在大房间边缘会撞到相机边界（`scrollX` 被 clamp），故改用纵向验证。

## 5. HUD 提示条

提示补上"Boss 红身=蓄力"后单行被右侧裁掉。改为短文案 + `fitHint()` 按 `scale.width` 等比缩放，640 宽与 360×800 竖屏均完整可见（`docs/screens/b2-room.png`、`b3-portrait.png`）。

## 已知未验

- 音效只验"解码与播放不报错"，听感未由人耳确认。
